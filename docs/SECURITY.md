# Безопасность и угрозы

## Прямое соединение (P2P)

Устройства стремятся соединиться напрямую. На практике за NAT часто нужны **STUN** (координация) и иногда **TURN** (ретрансляция). TURN технически — сервер, но не хранит содержимое чата; трафик остаётся зашифрованным на уровне WebRTC (DTLS/SRTP).

Альтернатива без интернет-серверов: Wi‑Fi Direct, Bluetooth, локальная сеть — тогда координаты передаются в зашифрованном виде вне приложения (QR и т.д.).

## Шифрование сообщений

- Симметричный ключ сессии выводится из X25519 + HKDF-подобного смешивания (см. код).
- Каждое сообщение защищено AEAD (целостность + конфиденциальность).
- Для личных чатов действует fail-closed политика: если у контакта нет X25519-ключа, запись/отправка в открытом виде блокируется.
- Для групп используется случайный ключ сообщения (`group DEK`), который доставляется участникам через подписанные X25519 key-envelope. Группы без X25519 ключей участников считаются незавершённо настроенными.
- При изменении состава группы (добавление/удаление участника или смена его X25519) выполняется ротация `group DEK`.
- После ротации участники должны выполнить синхронизацию (LAN/WebRTC), чтобы получить новый key-envelope и продолжить чтение новых сообщений группы.

## Динамический ID

Ротируемый peer ID снижает срок жизни «приглашений» и усложняет долгослежение по одному и тому же короткому коду. Он **не заменяет** проверку долгосрочного ключа при установлении доверия.

## IP

«Зашифровать IP» в классическом смысле нельзя для всего интернет-маршрута. Проект обеспечивает:

- шифрование **координат подключения** при обмене между пользователями (конверт на публичный ключ);
- отсутствие хранения IP в открытом виде в локальном хранилище приложения в демонстрационной модели.

Для анонимизации маршрута нужны отдельные инструменты (VPN, Tor и т.д.).

## Защита исходников и сборки

Используйте обфускацию и минимизацию на Android, релиз-сборки на всех платформах, не вшивайте секреты в код. Долгосрочные ключи — в Secure Storage / Keychain / DPAPI.

## Удаление данных и пределы гарантий

- Приложение ориентируется на **crypto-erasure**: при wipe сначала уничтожаются ключи и секреты, затем удаляются файлы.
- Дополнительно выполняется best-effort перезапись файлов приложения перед удалением.
- На Android нельзя дать 100% гарантию физического стирания всех исторических блоков из-за FTL/wear leveling, журналирования ФС и поведения контроллера флеш-памяти.
- Практическая цель: сделать возможные остатки на носителе криптографически бесполезными без ключей.
